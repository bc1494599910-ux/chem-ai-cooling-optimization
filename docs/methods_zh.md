# 怎样理解和讲解这个项目

这个首版研究的是：在声明的简化换热模型中，哪些面积和水流量组合能让
粗甘油出口不超过55°C，以及代理模型的误差是否会导致错误的设计建议。
所有训练标签由计算器生成；原报告提供基准输入，不是几千条实测数据。

## 先看运行链

1. `report_case.recalculate`：用附录B的1.667 kg/s和设计端点，复算报告。
2. `physics.forward`：输入面积、水流量、水入口温度，计算热负荷与两侧出口。
3. `design.make_grid`：列出101×101个候选；`pareto_front`找面积/流量取舍。
4. `data.generate`：独立生成训练、验证、普通测试、边界测试和范围外测试。
5. `surrogate.fit_models`：只用训练集拟合；验证集选择一个MLP初始化种子。
6. `surrogate.freeze_margin`：用验证资料选择保守温度裕量。
7. `design.compare_routes`：比较物理搜索、代理搜索及带裕量和复核的搜索。
8. `experiment.run`：串联流程并保存输入、结果、计时、图和版本指纹。

## 为什么不是把出口直接填成55°C

55°C是判定目标。一个固定面积、水流量的方案可能算出51°C，也可能算出60°C。
把所有输出都写成55°C，机器学习只能学到一个常数，无法比较设计。
低于55°C在本项目里表示冷却能力满足这项要求，不表示完成了真实生产的恒温控制。

## 两个基准为什么不同

报告复算沿用1.667 kg/s、总面积28.0373 m²；项目则精确换算6000/3600 kg/s，
默认采用扣除暂定管端长度后的有效面积27.5470 m²。两个配置的结果自然不同。
报告的315.112 kW是设计端点温差下的能力校核值。程序计算的实际模型热量必须
同时满足两侧能量衡算，不能拿这个能力值直接替代。

## 最值得检查的一个错误

代理预测54.8°C、参考模型得到55.4°C时，只有0.6°C偏差，却把不合格方案
判成了合格。定义危险方向为 `参考温度 - 预测温度 > 0`。
误接受率的分母是“代理判合格的数量”，不是全部测试样本。
边界样本专门集中在55±1°C，因此其误判率不能当作整个工况空间的发生概率。

## 优化在做什么

本版不输出人民币成本。比较的是面积和循环水流量，二者采用报告基准归一化。
不同权重代表不同偏好，没有一个权重是从报告证明的工厂经济最优。
网格扫描的最佳点是“当前有限网格里的最佳可行点”，不等于连续空间的全局最优。
循环水流量也不等于新鲜补水量。

## 为什么固定U需要写进限制

U可以粗略理解为在单位面积和温差下的整体传热能力。实际改变流速通常也会
改变传热系数。本版保留报告基准U，把流量影响只通过热容量流率体现出来。
这是为了得到一个清楚、可复算的起步模型；它的准确性不能扩展成真实设备保证。

## 你可以自己完成的小练习

在仓库根目录依次运行：

```powershell
uv run python -m cooling_project predict --area 20 --water-flow 8.971 --water-inlet 33
uv run python -m cooling_project predict --area 30 --water-flow 8.971 --water-inlet 33
```

运行前先预测哪一个出口更冷，再检查输出。然后到`config.Physics.hot_mass_flow_kg_s`
找到kg/h除以3600的位置，解释如果忘记换算会怎样影响热容量流率。

进一步可复制配置到新文件，把目标55改为54。预测温度本身不应改变，合格判定
及可行设计区域会改变。新的边界测试和设计评价也必须围绕新目标生成；不要拿
旧图冒充新目标结果。使用新的输出目录运行，不覆盖已有实验。
